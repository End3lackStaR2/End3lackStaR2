# ฝั่ง Arena — วิธีที่ผมอ่าน/เขียน bus

> เอกสารนี้คือ "สัญญา" ระหว่างคุณ (คนกลาง) กับผม (Arena) — อ่านคู่กับ `PROTOCOL.md`

## ข้อจำกัดที่ต้องบอกตรง ๆ ก่อน

| เรื่อง | สถานะจริง |
| --- | --- |
| ผมเรียก Friday ตรง ๆ | **ไม่ได้** — connector `mcp`/`hermes` = `unsupported` ในบทสนทนานี้ |
| ผมทำงานเองโดยไม่มีการพิมพ์จากคุณ | **ไม่ได้** — ผมตื่นเมื่อคุณส่งข้อความเท่านั้น |
| ผมอ่าน/เขียน repo นี้ | **ได้** (ทดสอบแล้วทั้ง push และ GitHub API) → จึงใช้ repo เป็น bus ได้ |
| Friday ทำงานบนเครื่องคุณ | **ได้** — โดยดึงงานจาก bus (pull) ไม่มีพอร์ตเปิดออกนอก |

**สรุปวงจร:** คุณพิมพ์สั่งผม → ผมเขียนงานลง `bus/queue/` → Friday หยิบไปทำ (ทุก 20 วิ) → Friday เขียนผลที่ `bus/results/` → คุณพิมพ์บอกผม "เช็ค bus" → ผมอ่านผลแล้วทำงานต่อ

## ข้อความที่ทำให้ระบบเดิน

| คุณพิมพ์มาแบบนี้ | ผมจะทำอะไร |
| --- | --- |
| `Arena เช็ค bus` | อ่าน `status/` → `queue/` → `results/` ล่าสุด → `requests/` แล้วสรุปให้ พร้อมบอกว่ามีอะไรต้องตัดสินใจ |
| `Arena สั่ง Friday ทำ X` | เขียน task ใหม่ลง `bus/queue/` (id `T-...`) แล้วบอกคุณว่า "ให้ Friday เปิด loop หรือสั่ง once" |
| `Arena ตอบ Friday` | อ่าน `requests/Q-*.json` แล้วเขียน `answers/Q-*.json` + อาจสร้าง task ต่อ |
| `Arena ตั้งค่า bus ให้ใหม่` | แก้ `PROTOCOL.md`/`actions.json.example` หรือเพิ่ม action ใหม่ (คุณต้องอัปเดต `actions.json` บนเครื่องด้วย) |

## รูปแบบงานที่ผมจะเขียน (สอดคล้องกับ PROTOCOL)

```json
{
  "schema": "friday.task/v1",
  "id": "T-20261015-00021",
  "created_at_utc": "2026-10-15T03:20:00Z",
  "created_by": "arena",
  "action": "hermes_doctor",
  "params": {},
  "lease_seconds": 900,
  "notes": "อยากเห็น paths + ผลทดสอบ key ทั้ง 2 ตัว ก่อนตัดสินใจขั้นถัดไป",
  "reply_via": "bus/results/T-20261015-00021.json"
}
```

**ผมจะใช้เฉพาะ action ที่มีอยู่ใน `actions.json` ของคุณเท่านั้น** ถ้างานที่ต้องการยังไม่มี action รองรับ ผมจะไม่พยายามเลี่ยงด้วย `powershell -Command ...` แต่จะบอกคุณให้เพิ่ม action นั้นก่อน (นี่คือด่านความปลอดภัยที่คุณถืออยู่)

## รูปแบบคำตอบของผม (`bus/answers/Q-*.json`)

```json
{
  "schema": "friday.answer/v1",
  "id": "Q-20261015-00007",
  "answered_at_utc": "2026-10-15T03:25:00Z",
  "answered_by": "arena",
  "answer": "4001 เกิดจาก key เก่าถูกเพิกถอน ... ขั้นต่อไปให้รัน hermes_verify",
  "next_tasks": ["T-20261015-00022"]
}
```

## สิ่งที่ผมจะทำและไม่ทำ

**จะทำ**
- อ่าน `results/*.json` แล้ววิเคราะห์ (exit code, stdout/stderr tail, เวลา)
- ออก task ถัดไปแบบทีละขั้น (ไม่ยิงรวดเดียว 10 งาน)
- เตือนถ้าผลลัพธ์ดูผิดปกติ (เช่น `refused` = action ไม่มีใน whitelist → ให้คุณเพิ่ม)
- เก็บ id ต่อเนื่องเพื่อ trace ได้ (T-… → Q-… → T-…)

**จะไม่ทำ**
- ไม่สั่งงานที่อยู่นอก whitelist ของคุณ
- ไม่ขอ token/webhook ของคุณในแชท (ใช้ไฟล์ในเครื่องเท่านั้น)
- ไม่เขียนทับ `bus/actions.json` (ไฟล์นั้นเป็นของคุณและ gitignore ไว้)
- ไม่ถือว่า task ที่ผมเขียนเป็น "คำสั่ง" — Friday จะตรวจก่อนรันเสมอ

## ตัวอย่างลำดับงาน (เคส Kick Pusher)

| ขั้น | ผมเขียน | Friday ทำ | ผมอ่านผลแล้วทำอะไร |
| --- | --- | --- | --- |
| 1 | `T-001` action `hermes_doctor` | รัน doctor | เห็น path/โปรเซส/ผลทดสอบ key → ตัดสินใจ |
| 2 | `T-002` action `hermes_fix` | ซ่อม + รีสตาร์ท + รอหลักฐาน | ถ้า `verdict=OK` → จบ; ถ้า `KEY_REJECTED` → ไปขั้น 3 |
| 3 | `T-003` action `kick_probe` | ทดสอบ key สด | ยืนยันว่า Kick หมุนใหม่ไหม → อัปเดต key ใน bus/config |
| 4 | `T-004` action `push_evidence` | เก็บ+ส่งหลักฐานขึ้น repo | ผมอ่านไฟล์หลักฐานจาก repo แล้วสรุปปิดเคส |

## ความเป็นส่วนตัวและความปลอดภัย

- ผลลัพธ์ที่ Friday ส่งขึ้น repo ผ่านการ **ปิดความลับ** อยู่แล้ว (token/JWT/webhook → `<redacted>`) แต่ Pusher app key ยังอ่านได้ (เป็น key สาธารณะ)
- ถ้าไม่ต้องการให้อะไรขึ้น repo เลย: ตั้ง `"read_only": true` (Friday จะดึงอย่างเดียว ไม่รันงาน) และ/หรือใช้ `collect_evidence` แล้วแนบไฟล์ในแชทแทน
- repo นี้เป็น **public** — ถ้าอนาคตมีงานที่ผลลัพธ์อ่อนไหว ให้ย้าย bus ไป repo ส่วนตัว (แก้ `repo_url` ใน `bus.config.json`)
